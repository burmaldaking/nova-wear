# NOVA WEAR — безопасность и документы

## Что уже сделано

- CSS и JavaScript вынесены во внешние файлы (`styles.css`, `script.js`), чтобы включить строгий CSP без `unsafe-inline` для скриптов.
- В `index.html`, `privacy.html` и `terms.html` добавлены:
  - Content-Security-Policy (meta);
  - Referrer-Policy `strict-origin-when-cross-origin`.
- В форме заказа:
  - обязательный чекбокс согласия на обработку персональных данных со ссылками на документы;
  - ограничения длины полей и проверка формата телефона;
  - персональные данные **не передаются в URL**: текст заказа копируется в буфер обмена, VK открывается без параметров с ФИО и телефоном;
  - после отправки показывается текст заказа и кнопка повторного копирования.
- Добавлены страницы `privacy.html` (политика конфиденциальности) и `terms.html` (условия заказа, доставки и возврата).
- Убраны неподтверждённые обещания «24/7» и «120+ моделей», заменены на нейтральные формулировки.
- Добавлен `.nojekyll` для корректной отдачи файлов на GitHub Pages.

## Обязательно заполнить до публикации

1. **Реквизиты продавца** — наименование (ИП/ООО), ИНН, ОГРН/ОГРНИП, юридический адрес. Замените все `[__]` в `privacy.html` и `terms.html`.
2. **Контакты** — реальные телефон, e-mail, адрес и часы работы в `index.html`, `privacy.html`, `terms.html`.
3. **Ссылка на VK** — `VK_GROUP` в `script.js` (сейчас `https://vk.ru/nightsf`).
4. **Цены, наличие, доставка, возврат** — проверьте, что все обещания на сайте соответствуют реальным условиям.
5. **Уведомление в Роскомнадзор** — если вы обрабатываете персональные данные как оператор, проверьте обязанность подать уведомление (ст. 22 152-ФЗ). Это зависит от вашей ситуации; уточните у юриста.
6. **Юридическая проверка** — документы являются шаблонами, а не готовыми юридическими заключениями.
7. **Зарубежный хостинг** — GitHub Pages размещён за пределами РФ. Если для вашей ситуации применимы требования о локализации персональных данных (152-ФЗ), оцените это с юристом. Сайт не хранит данные заказов на своём сервере, но хостинг может вести технические журналы.

## Технические ограничения GitHub Pages

GitHub Pages не позволяет задавать произвольные HTTP-заголовки. Поэтому:

- `X-Frame-Options`, `X-Content-Type-Options`, `Permissions-Policy`, HSTS через GitHub Pages **не выставить**;
- CSP работает через `<meta>`, но `frame-ancestors` в meta игнорируется;
- для полноценных заголовков используйте Cloudflare Pages, Netlify или собственный сервер — в репозитории есть файл `_headers` с рекомендованным набором (GitHub Pages его игнорирует).

На GitHub Pages обязательно включите **Settings → Pages → Enforce HTTPS**.

## Админ-панель менеджера

- Страница: `admin.html`. Вход по паролю (константа `ADMIN_PASSWORD` в `admin.js`, по умолчанию `novawear` — **смените перед публикацией**).
- Заказы сохраняются в `localStorage` браузера менеджера (демо-режим) и отображаются в панели: имя, телефон (кликабельный), товар, размер, цена, способ связи (написать/позвонить), мессенджер или удобное время звонка, комментарий, статус.
- Действия: позвонить (tel:), написать (Telegram/WhatsApp/SMS; для VK — копирование телефона), смена статуса, удаление, экспорт CSV, очистка.
- Ограничение: `localStorage` хранит данные только в браузере, где оформлен заказ. Чтобы заказы от всех покупателей приходили менеджеру, подключите бэкенд:
  1. Создайте Google Apps Script веб-приложение (или используйте Formspree/Web3Forms), которое принимает POST с JSON заказа и сохраняет в Google Sheet.
  2. Вставьте URL в `script.js`: `const ORDER_API = 'https://...'`.
  3. В `admin.js` добавьте GET-запрос к тому же URL для загрузки списка (сейчас — заглушка `fetchRemote`).
- Пароль на клиенте — не настоящая защита. Для реальной безопасности нужна серверная авторизация (или закрыть панель через basic auth на хостинге).


## Бэкенд для общих заказов (Google Apps Script)

Чтобы заказы от всех покупателей приходили менеджеру (а не хранились локально):

1. Создайте Google Таблицу.
2. Расширения -> Apps Script. Вставьте код из файла `apps-script.gs`.
3. Развернуть -> Новое развёртывание -> Веб-приложение: запуск от имени "Я", доступ "Все".
4. Скопируйте URL веб-приложения.
5. В `script.js` и `admin.js` установите `const ORDER_API = 'URL'`.
6. Заказы будут сохраняться в таблицу и загружаться в админ-панель на любом устройстве.
